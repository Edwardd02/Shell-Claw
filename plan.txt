
## 1. 技术栈选型

-   **后台守护进程 (Daemon)**：使用 Rust (基于 tokio 和 Unix Socket) 实现。提供极致性能与内存安全，零 GC 停顿，冷启动与运行期 CPU/内存开销极低。
    
本地 LLM 推理引擎：采用现有的成熟 Rust 绑定库（如 llama-cpp-rs，参考仓库：[https://github.com/utilityai/llama-cpp-rs](https://github.com/utilityai/llama-cpp-rs)）。可将其克隆/下载至项目的 reference/ 目录中，由 Agent 在开发前自查并筛选其中最适合调用的 API 模块与文件。基于 llama.cpp 底层提供 Safe Rust 封装，利用原生 C++ 极致优化，支持 macOS Metal 和 Linux AVX2 硬件加速，并支持内存锁定 (mlock)。无需手动编写和维护任何 C++ FFI 代码，从根源规避内存泄漏隐患。
    
-   **基准端侧模型**：选用 Qwen/Qwen3-0.6B-Base（huggingface：Qwen/Qwen3-0.6B-Base）。仅占用约 500MB 显存/内存，预训练吞吐海量代码与 Shell 脚本，首字延迟小于 15ms。
    
-   **本地记忆与检索数据库**：采用 SQLite3 (rusqlite) 并开启 FTS5 全文索引。作为单文件零配置数据库，提供极速 BM25 检索（查询耗时小于 2ms）。
    
-   **Shell 前端挂载 Hook**：基于 Zsh Async ZLE 和 Unix Socket 交互。通过异步非阻塞通信将击键推导完全解耦，确保主终端输入零卡顿。
    
-   **零配置分发与服务管理**：基于 Homebrew Formula 结合 launchd 或 systemd。利用 Homebrew Services 实现后台进程自动开启与自启，完全免去用户手动配置。
    

## 2. 系统架构与双进程交互流程

系统采用“前端轻量 Hook + 后端 Rust 常驻守护进程”的双进程解耦架构，两者通过本地 Unix Domain Socket (`/tmp/smart-shell-copilot.sock`) 进行低延迟 JSON-RPC 通信。

系统处理用户输入的完整流水线如下：

1.  **输入捕获与防抖**：用户在终端打字输入，终端产生击键事件。轻量级 Zsh 异步 Hook 进行 30ms 防抖拦截，若用户持续高速击键则自动丢弃过期的中途请求。
    
2.  **异步 IPC 传输**：Zsh Hook 将当前命令行文本、工作目录 (cwd) 和上下文参数构造成 JSON-RPC 请求，通过 Unix Socket 发送到后台守护进程。
    
3.  **后台任务调度**： Rust 守护进程接收请求，首先取消上一次未完成的推理任务（若存在）。
    
4.  Fast RAG 记忆检索：守护进程并发查询 SQLite FTS5 数据库，检索当前工作目录及历史高频匹配命令作为 Prompt 上下文。
    
5.  **模型约束推理**：守护进程将 Prompt 投入 llama.cpp，复用预热好的 KV-Cache，并通过 GBNF 语法强行限制模型仅输出单行命令后缀。
    
6.  **补全渲染**：守护进程将预测结果通过 Socket 返回给前端，Zsh Hook 在光标右侧将后缀渲染为灰色的 Ghost Text（虚影文字），用户按 Tab 键即可一键采纳。
    

## 3. 零配置安装与无感开启实现方案

为了实现用户在执行 `brew install` 后无需手动修改 `.zshrc` 即可即装即用，系统采用以下三层自动注入与管理机制：

### 3.1 自动后台服务注册 (Homebrew Services)

在 Homebrew Formula 中配置 `service` 脚本，安装完成后自动注册后台守护进程。在 macOS 系统上自动注册并启动 `launchd` plist 配置文件实现开机自启；在 Linux 系统上自动注册 `systemd` 用户级服务。

### 3.2 自动 Shell 钩子加载 (Global Shell Autoload)

安装包自动向系统包管理器环境或全局 Shell 加载点（如 `/etc/zsh/zshrc`）注入一行轻量异步载入逻辑。当用户打开任意新终端窗口时，钩子通过 Unix Socket 探测后台守护进程是否存在。若守护进程活跃则自动激活补全功能；若守护进程未运行，则静默退回原生终端交互，不产生任何错误提示。

### 3.3 卸载清理 (Zero Residual)

当用户运行 `brew uninstall` 时，自动触发卸载钩子，停止后台进程并清除全局配置文件与系统服务注册项，保证零残留。

## 4. 数据存储与 Fast RAG 算法设计

### 4.1 SQLite 记忆库 Schema

SQL

```
-- 历史命令记忆表
CREATE TABLE IF NOT EXISTS command_history (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    cwd TEXT NOT NULL,                     -- 执行路径 (项目级隔离)
    command TEXT NOT NULL,                 -- 完整命令行
    last_used_at INTEGER NOT NULL,         -- Unix 时间戳
    use_count INTEGER DEFAULT 1            -- 使用频次
);

-- FTS5 全文检索虚拟表
CREATE VIRTUAL TABLE IF NOT EXISTS command_fts USING fts5(
    command,
    content='command_history',
    content_rowid='id'
);

```

### 4.2 混合检索排序公式

针对终端命令行场景，联合文本相似度（BM25）、路径匹配度与时间衰减因子进行综合排序（检索全过程耗时小于 3ms）：

$$\text{Score} = w_1 \cdot \text{BM25}(\text{query}) + w_2 \cdot \mathbb{I}(\text{cwd\_match}) + w_3 \cdot \log(1 + \text{count}) \cdot e^{-\lambda \Delta t}$$

## 5. 推理引擎与 GBNF 采样强约束

为确保 0.5B 小模型输出绝对收敛、零废话且严禁产生多行 Markdown 或解释性文字，在推理阶段施加 GBNF (Grammar-Based Backus-Naur Form) 采样约束。

### 5.1 GBNF 语法规则 (`single_line.gbnf`)

EBNF

```
# 约束输出仅为单行文本，遇到换行符或 EOF 立即终止采样
root        ::= text-line
text-line   ::= [^\r\n\x00]+

```

### 5.2 KV-Cache 预热机制

守护进程启动时自动将模型载入物理内存并执行 `mlock` 防止被交换到磁盘。系统 Prompt（包含通用指令约束）的 KV-Cache 保持永久常驻，每次打字触发预测时仅需计算极小增量文本，Prefill 耗时控制在 5ms 以内。

## 6. 分步实施路线图

-   **Phase 1: 核心引擎与管道搭建**
    
    -   基于 Rust 搭建 Daemon 主框架与 Unix Domain Socket 服务。
        
    -   集成 `llama-cpp-rs`，加载 `Qwen2.5-Coder-0.5B-Instruct` 模型并配置 GBNF 单行采样约束。
        
    -   编写 Zsh 异步 Client 客户端脚本，验证打字到 Ghost Text 呈现的全链路。
        
-   **Phase 2: Fast RAG 记忆层与算法优化**
    
    -   集成 `rusqlite` + FTS5 全文索引，实现命令历史的自动采集与静默更新。
        
    -   实现包含 BM25、路径关联与时间衰减的混合排序算法。
        
    -   优化防抖逻辑（Debounce）与多级任务取消机制，将端到端延迟压至 20ms 以内。
        
-   **Phase 3: 无感安装与 Homebrew 分发**
    
    -   编写 Homebrew Formula 以及 macOS `launchd` 与 Linux `systemd` 自动化服务配置文件。
        
    -   实现全局 Shell 钩子静默注入与卸载清理逻辑。
        
    -   开展全平台（macOS Intel/Apple Silicon, Linux x86_64/AArch64）兼容性与性能测试。
