
# Shell Claw


## 1. 背景与问题定义 (Problem Statement)

在日常开发中，命令行（Terminal/Shell）是开发者最高频的交互界面之一。然而现有解决方案存在显著痛点：

1. **传统 Shell 补全过于机械**：如 `zsh-autosuggestions` 仅依赖字符串的前缀历史完全匹配，无法理解当前目录上下文、参数语义或复杂操作模式。
2. **云端 AI Copilot 延迟与隐私问题**：基于云端大模型的终端补全通常有数秒延迟，破坏打字连贯性，且存在将敏感路径、环境变量或私有代码泄漏至云端的风险。
3. **缺乏“个人黑话”与习惯记忆**：开发者对于相同工具（如 Docker, Git, Kubernetes）有着极强的个人使用偏好，现有工具无法自动拟合个人习惯。

**目标 (Why)**：构建一款**零配置安装、零延迟感、完全离线、越用越懂用户的端侧命令行智能补全工具**，通过 `brew install` 即可实现无感开启，像 LLM 驱动的拼音输入法一样在用户打字时无缝预测命令。

---


## 2. 核心功能需求 (Core Functional Requirements)

### 2.1 零配置无感安装与自启动 (Zero-Touch Onboarding)

-   **一键安装即用**：通过包管理器（如 Homebrew）安装后，无需用户手动修改 `.zshrc` / `.bashrc` 或手动配置复杂的配置文件。
    
-   **服务与 Hook 自动挂载**：安装完成时，后台记忆进程自动注册并启动；新建的终端窗口自动加载轻量补全 Hook。
    
-   **静默式历史积累**：安装完成后即刻在后台静默建立索引，自动学习用户后续在各目录下的命令记录，无需人工触发“训练”或“导入”流程。
    

### 2.2 毫秒级 Ghost Text 智能补全

-   **实时预测**：用户在终端打字时，光标右侧以灰色虚影文字（Ghost Text）实时呈现推荐的命令后缀。
    
-   **一键采纳**：用户按 `Tab` 键或 `右方向键` 可瞬间采纳补全建议；直接继续打字则自动覆写。
    
-   **单行严格收敛**：补全内容**必须且仅为单行**剩余命令字符串，严禁产生多行文本、Markdown 代码块或解释性废话。
    

### 2.3 本地习惯与上下文记忆 (Personal Pattern Memory)

-   **项目关联**：在不同的工作目录下，优先推导该项目或该类型仓库的高频使用指令。
    
-   **个人习惯自动拟合**：无需用户手动配置 Alias，系统能自动捕捉用户高频使用的复杂命令组合（如带有特定参数的 `docker run` 或 `git` 选项）。
    
-   **错误与修正联动**：当上一条命令执行失败时，系统能够基于历史纠错行为，优先推荐纠错后的命令。
    

### 2.4 极致隐私与离线保证

-   **100% 本地运行**：所有历史记录分析、语义推导与补全生成均在本地设备完成。
    
-   **零数据上报**：绝不向任何外部网络发送命令文本、目录结构或环境变量。
    

## 3. 用户故事与验收标准 (User Stories & Acceptance Criteria)

### 用户故事 1：零配置无感开启体验

-   **作为一名** 追求高效且不愿折腾配置文件的开发者，
    
-   **我希望** 仅执行 `brew install <tool>` 后即可完成所有初始化，
    
-   **以便于** 我打开新终端窗口时立刻享受 AI 智能补全和记忆功能，无需手动编辑 `.zshrc`。
    
-   **验收标准**：
    
    -   执行安装命令后，后台记忆守护进程自动启动并开机自启。
        
    -   打开新终端窗口，打字时即可直接看到灰色 Ghost Text 补全。
        
    -   整个过程无需手动运行任何初始化命令或改写 Shell 配置文件。
        

### 用户故事 2：高频复杂命令的快速补全

-   **作为一名** 经常使用复杂 CLI 参数的开发者，
    
-   **我希望** 敲出命令前几个字母时，终端能自动显示出我平时最常用的完整参数选项，
    
-   **以便于** 我无需反复查阅 `help` 或翻找历史记录。
    
-   **验收标准**：
    
    -   打字停止后（<30ms 内），光标右侧出现灰色的补全建议。
        
    -   建议内容与当前路径及用户历史行为高度吻合。
        
    -   按 `Tab` 采纳后，光标平滑移动至行尾，可直接回车执行。
        

### 用户故事 3：无感干扰与极速响应

-   **作为一名** 打字速度极快的终端用户，
    
-   **我希望** 智能补全不会造成终端输入卡顿或跳字，
    
-   **以便于** 我的打字节奏不被打断。
    
-   **验收标准**：
    
    -   智能补全在后台异步运行，若用户持续击键，系统自动撤销上一次未完成的预测。
        
    -   终端交互主线程 CPU 占用极低，毫无卡顿感。
        

## 4. 约束条件与边界 (Constraints & Invariants)

1.  **硬性边界 (Strict Boundary)**：不支持且严禁实现多轮对话框、Markdown 格式化输出或交互式 AI 聊天界面。本项目**专注于极速命令行补全**这一单一场景。
    
2.  **零侵入原则 (Zero Intrusion)**：卸载工具时（如 `brew uninstall`），必须能自动清理全部后台服务与环境变量，不留下任何残留钩子或破坏原 Shell 流程。
    
3.  **无感兼容**：不改变 Shell 原生快捷键习惯，完全兼容现有的终端主题与环境变量。
