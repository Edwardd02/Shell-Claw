# 项目宪章与开发指南：Smart Shell Copilot (Project Constitution)

本文档依据 `/speckit.constitution` 规范制定，为 Smart Shell Copilot 项目的最高开发准则与质量治理规范。所有后续的功能设计、架构重构、代码实现及 Code Review 均须严格遵循以下四大核心原则。

---

## 1. 代码质量原则 (Code Quality Principles)

* **严格的内存与并发安全**：核心后台守护进程全面采用 Rust 语言构建。除非在必须调用 `llama.cpp` C++ FFI 绑定的极少数场景，严禁使用 `unsafe` 代码块；任何 FFI 调用必须封装在安全的抽象层之内，并在入口处完成空指针与边界条件的严格校验。
* **分层解耦与模块独立**：项目严格划分为 Shell Hook（前端通信层）、Rust Daemon（任务调度与 IPC 层）、SQLite Fast RAG（记忆检索层）以及 llama.cpp FFI（推理引擎层）。层与层之间仅通过明确的 Trait 接口或 JSON-RPC 数据包交互，禁止产生跨层直接依赖。
* **无感容错与静默降级**：终端是开发者最高频且最敏感的工作环境。守护进程运行期间发生的任何非致命异常（如 SQLite 锁冲突、模型推理超期、Socket 瞬间中断），系统必须自动执行静默降级并回退至原生 Shell 行为，严禁向终端输出 Panic 堆栈日志或报错提示信息，确保不干扰用户的正常输入。

---

## 2. 测试标准 (Testing Standards)

* **端到端延迟自动化门禁**：在 CI/CD 流水线中构建自动化 Latency Benchmark 测试，持续监控从模拟击键触发、Socket 传输、FTS5 检索、模型增量推理到 Ghost Text 渲染的全链路耗时。一旦端到端延迟超过 30ms 阈值，禁止合并代码。
* **高覆盖率单元与集成测试**：Rust 守护进程中的任务调度逻辑、防抖/取消机制以及 SQLite 混合排序算法（BM25 + 路径关联 + 时间衰减）必须具备完善的单元测试，核心代码行覆盖率不得低于 85%。
* **多平台与多 Shell 兼容性验证**：所有版本发布前必须在 macOS (Intel / Apple Silicon) 及主流 Linux 发行版（Ubuntu, Arch Linux）下，对 Zsh 与 Bash 环境进行自动化兼容性测试，重点验证 `brew install` 后的服务自动挂载与 `brew uninstall` 后的零残留清理。

---

## 3. 用户体验一致性 (User Experience Consistency)

* **Ghost Text 形式严格收敛**：智能补全在终端内必须且仅能以灰色虚影文字（Ghost Text）的形式呈现于光标右侧。补全建议必须严格收敛为单行剩余命令字符串，绝对禁止产生多行文本、Markdown 代码块、弹窗交互或任何形式的 AI 对话界面。
* **无感按键响应与零习惯侵入**：补全交互严格遵循标准输入习惯——按 `Tab` 键或 `右方向键` 瞬间采纳补全，继续正常打字则无缝覆写补全建议。系统不得更改或拦截 Shell 原生的任何快捷键定义。
* **零配置（Zero-Touch）产品体验**：产品的使用体验必须保持高度一致的“开箱即用”。用户通过包管理器安装后，系统自动完成后台 Service 注册与 Shell 钩子挂载，无需强制用户手动编辑 `.zshrc`、修改配置文件或执行额外的初始化命令。

---

## 4. 性能要求 (Performance Requirements)

* **极致资源控制**：守护进程常驻运行时的物理内存（RSS）占用必须严格控制在 600MB 以内（含 0.5B 模型的物理内存锁定）。在后台空闲无击键状态下，CPU 占用率必须无限接近 0%。
* **毫秒级检索与推理**：SQLite FTS5 混合检索耗时必须小于 3ms；llama.cpp 推理引擎须通过 KV-Cache 常驻预热与 GBNF 语法采样强约束，将 Prefill 与增量 Decode 首字延迟控制在 15ms 以内。
* **主线程绝对异步非阻塞**：Shell Hook 与后台守护进程之间的一切 IPC 通信与任务调度必须在独立的异步线程池中完成。无论后台计算或模型推理处于何种状态，绝不得阻塞 Shell 交互主线程，确保用户打字过程零跳字、零卡顿。
