## [高优先级] 一次性命令不应进入长期记忆

**问题**
用户执行一次性命令（如 `git clone git@github.com:xxx/repo.git`、`cd /tmp/xxx`）时，
hook 的 `memory.record` 会把它存入本地记忆。此后用户输入相同前缀（如 `git clo`），
每次都建议这个一次性命令，干扰真正高频/可复用的命令补全。

**期望行为**
- 可识别为"一次性"的命令（含 URL、临时路径、随机目录名、git clone 等）
  不写入长期记忆，或降低其排序权重。
- 目标：记忆积累的是"可复用、高频"的命令习惯，而非一次性操作。

**实现思路（待深挖）**
- 检测命令中是否含 URL / 明显占位性质的内容（`git@github.com`、`https://`、
  `$HOME`、`/tmp/` 等）→ 判定为一次性，跳过 `record_command` 或标记弱保留。
- 或：对 `clone`、`mv`、`rm` 等"结果不可复用"命令降低记忆权重。
- 涉及：`crates/daemon/src/scheduler/mod.rs` 的 `record_command` 决策逻辑。

## [中优先级] 训练数据质量：清洗 Windows 污染

**观测**
- 微调后 `mv` → `-WhatIf`、`cp` → `--parents` 等输出显示 **PowerShell 风格参数**，
  说明 tldr 数据中混入了 Windows/非 Unix 命令，污染了模型对 Unix 命令的认知。
- 需要清洗：保留高质量 Unix 命令，剔除 Windows/PowerShell/cmd 特有命令。

**清洗方向**
- tldr 提取时按平台过滤（`pages/common` 混平台，`pages/windows` 是纯 Win）。
- 剔除 PowerShell 特有参数风格（`-WhatIf` 等），甄别 Unix 是否有对应。
- 建立 Unix-only 命令白名单或 Windows 命令黑名单。

## [中优先级] 微调模型：结构化提取 tldr 数据训练命令补全

**背景**
本地 0.5B 模型在"无记忆命令"上补全能力弱（`pip insta`、`brew upd` 等输出不稳）。
计划从 `tldr` 仓库结构化提取训练数据，微调 `Qwen/Qwen3-0.6B-Base`（目前只有
safetensors，需转 GGUF）使其学会 shell 命令补全。

**数据要点**
- tldr 结构：描述 + 实际命令，覆盖 4604 个常见命令（`pages/common/`）。
- 训练时剥离占位符 `{{...}}`（如 `{{https://example.com/repo.git}}` 不保留）。
- 训练对：`(命令前缀, 补全后缀)`。

**待定**
- 训练框架（LoRA via unsloth/peft）、训练环境（本机 M4 / Colab / 云 GPU）。
- tokenizer 策略（用户提过"逐字母 token"，需评估 vs 默认 subword 的取舍）。

## [待评估] idea：频次加权训练

**想法**
有的命令使用频次天然高（`ls`、`cd`、`git status`），训练时应让高频命令
占据更高权重，使模型更偏向补全常用命令。

**方向**
- 用命令出现频次（tldr 页面热度 / 常见度 / 社区使用统计）作为样本加权。
- 或对高频命令重复采样，形成"更常见 = 更大概率出现"的先验。

---

## [待评估] idea：一次补全 1-2 个词，循环展示

**想法**
`ls` 后面可跟一堆后缀，但用户可能只想要 `ls -a`。与其一次补全整个长后缀，
不如**每次只建议 1-2 个词**（如先 `-a`），用户接受后再继续提示下一个后缀。
又快又好，减少长建议的"猜中率"压力。

**方向**
- 训练时让"目标后缀"更短（1-2 个词）。
- 或推理后按词截断，接受后触发二次补全。
- 与现有"接受 Tab/右箭头"机制结合，形成"逐步补全"。
